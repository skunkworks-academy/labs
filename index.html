A simple learner journey with the right control points.

Use the Academy identity to select a lab and the required duration. Learners never receive a shared cloud credential.

02

Pay through a trusted provider

03

Designed for delivery

Useful to a learner, manageable for an instructor, safe for the platform.

Guided, not generic

Every lab has clear outcomes, a task sequence, evidence checkpoints and reset criteria so practical time maps to a recognised skill.

Private by default

Lab runners use private networking, short-lived access and restricted outbound paths. The first lab exposes no Google Cloud console or public SSH/RDP endpoint.

Built to scale deliberately

Pre-warmed slots make common labs fast to launch. Separate project-per-learner cloud labs are introduced only after cost, isolation and cleanup controls are proven.

Help shape the first Labs release.

Pilot participants receive a guided Linux lab, completion feedback and a direct route to report usability or environment issues. This lets the first paid release meet the standard required for wider Academy delivery.

Help and readiness

What to expect next.

When will I be able to pay and launch immediately?

Immediate self-service access is switched on after PayFast, PayPal, Entra identity and the GCP runner controls have passed production verification. Until then, pilots are issued as managed entitlements.

Will I receive Google Cloud credentials?

No. The first lab is a browser-based Linux environment. Advanced Google Cloud exercises will use constrained, isolated projects only where the learning outcome requires it.

What happens when a session ends?

Sessions expire after their allocated time or an idle period. The runner is terminated or reset, and a reconciliation process checks for resources that were not released as expected.

How do I request a cohort or instructor-led lab?

Email the training team with your technology topic, learner count, target date and required duration. We will recommend a secure, repeatable delivery design.

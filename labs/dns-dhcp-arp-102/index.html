Module 1

Give each protocol one clear job.

A normal user symptom can sit on top of several layers. Start by separating the evidence source from the conclusion you can reasonably draw.

Configuration

DHCP gives a client usable parameters.

In this lab: IPv4 address, prefix, default gateway and DNS server. A lease is not a successful website request.

Name resolution

DNS answers a name-to-address question.

A returned address is useful evidence, but it does not prove routing, policy or the application service is healthy.

Local delivery

ARP finds a local layer-2 address.

For an off-subnet destination, the client normally resolves the default gateway's MAC address - not the remote server's MAC.

1

Receive configuration

The client obtains a valid lease and learns its gateway and resolver.

2

Ask for a name

The client queries its configured DNS resolver for the requested hostname.

3

Find the next hop

The client resolves the local gateway's MAC address when traffic must leave the subnet.

4

Reach the service

Routing, policy and application health still determine whether the actual request succeeds.

Useful habit: record the question first. For example: “Did the client receive a valid address, gateway and resolver?” That question produces a smaller, safer test than “Why is the network broken?”

Module 3

Choose the earliest safe troubleshooting check.

Later symptoms may be tempting, but a useful triage step confirms the first missing dependency and preserves the result for the network owner.

Case file: training-floor-04

A learner device cannot reach the internal portal.

Fictional case

Observed symptom

Time
09:25 local time
User report
“The portal name does not open.”
Client address
169.254.88.12 with no configured DNS server
Scope
One training device; no changes have been authorised.

Interpret carefully: a link-local-style address and empty resolver setting are observations that point back to configuration. They are not proof that every network component is broken.

What to preserve

  • Time and physical/virtual location.
  • Address, prefix, gateway and resolver values displayed by the client.
  • Whether the issue is isolated or affects a defined group.
  • The approved escalation channel and ticket ID.

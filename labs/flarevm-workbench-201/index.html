Lab summary

Design a Windows analysis workbench that can be trusted and reset.

  • 01
    Explain why a VM, a known-good snapshot and restricted networking are baseline controls.
  • 02
    Capture PE metadata, strings and tool provenance before any dynamic interpretation.
  • 03
    Read process, file and simulated-network telemetry as a correlated timeline.
  • 04
    Define the stop, preserve and reset actions that return an analysis workstation to known-good state.
!

Do not turn off protections on a personal or production device

FLARE VM’s upstream installer is intended only for a VM and may alter host protections during installation. This Academy lab does not ask learners to install it, download a script, disable endpoint protection or execute a sample. Use only an Academy-approved, staff-managed image when a live lab is released.

Module 1

Build for repeatability, not convenience.

A good Windows analysis environment has a documented image version, a recovery point, restricted networking and a clear scope for any supplied training artefact. The upstream FLARE VM project explicitly states that it should only be installed on a VM.

Immutable base

Build once, verify often.

Staff own the baseline and package updates; learners receive a constrained session.

Snapshot

Recover after every run.

A clean point exists before installation, fixtures or analysis activity.

Network policy

Host-only by default.

Do not bridge an analysis image to an office or home network.

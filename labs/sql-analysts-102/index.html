SQL for analysts - ask a precise question, return only the data needed and explain the result.

SQL is a language for working with structured data, but the real analyst skill is reasoning: define the question, understand the tables, select only the fields needed, join data with a known relationship, aggregate carefully and communicate the limit of what the result proves.

Module 1

Start with a bounded question and the minimum fields that answer it.

Before writing a query, describe the result in ordinary language. For example: “Which beginner labs were completed in July, and how many completions did each receive?” That wording suggests a time filter, a course level field, a completion status and an aggregate grouped by lab. It does not require learner email addresses, passwords or every row in every table.

-- Question: How many completed beginner labs were recorded in July?
SELECT lab_code, COUNT(*) AS completions
FROM completion
WHERE status = 'completed'
  AND completed_at >= '2026-07-01'
  AND completed_at <  '2026-08-01'
GROUP BY lab_code;

Synthetic illustration - not executed by this page.
Analyst discipline: retrieve the least data required for the approved question. A broad SELECT * can expose fields the analysis does not need, complicate review and create unnecessary data-handling risk.

Module 2

Join tables only after you know the relationship and desired row meaning.

A join combines rows based on a relationship. The key is not just syntax: you must know which field identifies a learner, lab or completion and whether each side can have one or many matching rows. In the fictional model below, one learner can have many completions, and one lab can have many completions. A completion row links a learner to a lab.

Join review questions

  • What does one output row represent?
  • Which key relates the two tables?
  • Could multiple matches multiply rows?
  • Do you need all rows or only matching rows?
SELECT l.lab_code, l.title, COUNT(c.completion_id) AS completions
FROM lab AS l
JOIN completion AS c
  ON c.lab_code = l.lab_code
WHERE c.status = 'completed'
GROUP BY l.lab_code, l.title;

The JOIN condition states how the rows relate.

Module 3

Aggregate carefully, then state what the result does and does not prove.

Aggregate functions combine values across rows. COUNT can count events; SUM can total a numeric measure; AVG can calculate an average; and GROUP BY partitions the calculation by a shared dimension. A result can show a pattern, but it does not by itself explain why the pattern exists or establish causation.
